Passkey-PRF unlock — N independent methods, one key (header-free)

The DB's key (DEK) is not stored. It is wrapped by an envelope with one slot per unlock method. Add a passkey, a second passkey, a written recovery code — each wraps the same DEK, so any one opens the DB and losing one loses nothing. Adding/removing a method re-wraps the DEK; it never re-encrypts the database.
